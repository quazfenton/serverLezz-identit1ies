# PLAN0812

High-signal notes on actions/modules/states/params/flows/methodologies for the Coordination Cosmos project. This document is the living plan to drive the codebase to production, while capturing design intent and outstanding work.

## Current Architecture (observed)

- Backend
  - `backend/server.ts`: Express server + WebSocket, in-memory stores with JSON file persistence, initializes mechanisms: `NetworkManager`, `ProfileManager`, `RecommendationEngine`, `OptimizationEngine`, `CloudModelEngine`, `AgentManager`, `BehaviorObserver`, `HighDimSimulation`.
  - Real-time broadcasts, sample data initializer, periodic optimization, metrics collection.
  - Endpoints: profile CRUD (simplified), listings, coordination creation, matches, optimize, health/metrics.
  - Uses `shared/types.ts` types across modules.

- Mechanisms
  - Agents: demo nodal agents + mock orchestrator for P2P-style matching (under `mechanisms/agents/` and `mechanisms/llmOrchestration/orchestrator.ts`).
  - Cloud Models: previously over-scoped; now minimal `CloudModelEngine` used by server with stubs for `enhanceProfile`, `optimizeMatching`, `optimizeSystemPerformance`.
  - Network: in-memory graph (`NetworkManager`) with decaying edges and recommendations.
  - Profiles: `ProfileManager` with behavior-driven weight updates.
  - Recommendation: network + behavior fusion.
  - Optimization: NSGA-II style skeleton for resource allocation and matching.
  - Simulation: high-dimensional interaction simulator wiring network + profiles.

- Frontend
  - `frontend/App.tsx`: Canvas-based "Aura" visualization, WebSocket client, onboarding, resonance filter, interactions. Now exported for `main.tsx` to render.
  - `frontend/main.tsx`: React bootstrap and error boundary.

- Shared Types
  - `shared/types.ts`: Expanded with concrete `Profile`, `ServiceListing`, graph, metrics, optimization, and matching types. Back-compat for demo agent fields:
    - `PlatformItem.type?: string` and optional `transactionType/category` to support both demos and future richer schema.

## Key Data Models (canonical)

- Profile: identity, `resources` (goods/skills/needs/time), `reputation`, `economicProfile.valueAlignment`, `behaviorProfile`.
- ServiceListing: normalized listing representation for frontend + backend.
- Network: `GraphNode { profile, connections[], weight, lastInteraction }`, `GraphEdge { source, target, weight, lastUsed }`.
- MatchingResult: `profileA`, `profileB`, `matchScore`, optional dimension breakdown.
- SystemMetrics/SystemState for monitoring and broadcast.
